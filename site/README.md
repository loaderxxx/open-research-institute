# Двуязычный сайт ORI — локальная реализация

[English](README.en.md)

Статус: подготовлено локально, не развёрнуто. Историческая запись рабочего сайта находится в DEPLOYMENT.md и не описывает эту ревизию.

## Запуск и проверка

Из корня репозитория выполните `npm start`; откройте http://localhost:3000/en/ или http://localhost:3000/ru/. `npm test` проверяет HTTP и почтовый адаптер. Тесты используют подменённого почтового провайдера и не отправляют писем. `npm run translations` обновляет реестр переводов публичных документов. Основной язык сайта — английский. Переведённый каталог не означает, что полные обзоры по ссылкам переведены.

Сервер отдаёт только явно разрешённые публичные файлы, включая PDF и Markdown из каталога. Исходник сервера и конфигурация не доступны. Контекст сборки должен содержать весь репозиторий: этой версии нужны каталог и обзоры вне `site/`. При развёртывании на Railway измените корень сервиса с `/site` на корень репозитория и используйте `npm start`, только после разрешения на выпуск. Не меняйте существующий деплой ради просмотра этой работы.

## Запросы на исследование

Получатель, утверждённый владельцем: **im@vladimiruzbek.com**, закреплён на сервере. Поля: тема (3–180 символов), вопрос (10–6000), email отправителя, необязательное имя (до 120) и скрытое поле защиты от спама. Запросы отправляются JSON на `POST /api/research-requests`. Имя, email и сообщение передаются через настроенного почтового провайдера владельцу для рассмотрения; отправка не обещает исследования или срока ответа. Не запрашивайте у посетителей чувствительные данные.

Подготовленный адаптер использует [API отправки Resend](https://resend.com/docs/api-reference/emails/send-email). Аккаунт провайдера не создан, расходы не разрешены, домен не настроен, письма не отправлены. Настройте `RESEND_API_KEY`, `MAIL_FROM` (разрешённого проверенного отправителя) и точный `SITE_ORIGIN` (схема и хост, без завершающего слеша) в секретах хостинга. Не помещайте секреты в Git или чат. Переменные должны быть доступны процессу Node; `.env.example` — документация, а не автоматически загружаемая конфигурация.

Без настройки корректные заявки получают 503; посетитель может использовать видимую ссылку прямого email. Ответ 202 означает принятие сообщения провайдером, а не доказанную доставку в ящик. Ошибки провайдера возвращают 502; неудачные заявки скрыто не сохраняются. Приложение не пишет содержание сообщений и ключи API в журнал.

Сервер проверяет поля, принимает JSON с того же источника, ограничивает размер запроса, применяет скрытое поле против ботов и лимит запросов. Лимит в памяти — пять попыток на IP соединения за 15 минут; перезапуск его сбрасывает. За обратным прокси посетители могут разделять лимит; переданным IP-заголовкам намеренно не доверяем. Перед публичным трафиком настройте ограничение на доверенном входном прокси и проверьте его поведение. Несколько экземпляров сервера не разделяют этот счётчик. Одинаковые принятые запросы дедуплицируются в памяти на 15 минут и используют постоянный ключ идемпотентности провайдера. Постоянного ящика заявок и очереди повторных отправок в приложении нет.

## Что ещё проверить перед выпуском

- Подтвердить отправителя и аккаунт провайдера с владельцем.
- Проверить доставку в утверждённый ящик и Reply-To одной отдельно разрешённой реальной отправкой.
- Проверить оба языка, мобильный вид, ссылки каталога и документов, ошибки и защиту от спама на целевом хостинге.
- Завершить и проверить отсутствующие полные переводы и скачиваемые версии презентации, прежде чем называть весь корпус двуязычным.
- Получить разрешение, покрывающее публикацию/развёртывание. Существующий рабочий сайт остаётся без изменений.
