## Запуск и проверка

Страницы программ доступны по `/ru/research/<slug>/` и `/en/research/<slug>/`; библиотека — `/ru/library/` и `/en/library/`; методы и протоколы — `/ru/methodology/` и `/en/methodology/`. Страницы формируются на сервере и доступны без JavaScript. Двуязычная повестка находится в `site/research-programmes.json`; `data/reading-library.json` содержит только опубликованные обзоры. Исторические адреса Markdown сохранены. При изменении шаблона или повестки перезапустите сервер.

Каждая программа содержит блок «Материалы и источники»: прямые ссылки на книги, публикации и исследователей и переход к полной подборке с аннотациями. На главной и в библиотеке показаны счётчики материалов. `site/research-resources.js` читает двуязычные `programs/<slug>/RESEARCH_MAP.md` и `RESEARCH_MAP.en.md`, поэтому ссылки обновляются вместе с картами литературы. После изменения карт перезапустите сервер.

Из корня репозитория выполните `npm start`; откройте http://localhost:3000/en/ или http://localhost:3000/ru/. `npm test` проверяет HTTP и почтовый адаптер. Тесты используют подменённого почтового провайдера и не отправляют писем. `npm run translations` обновляет реестр переводов публичных документов. Основной язык сайта — английский. Полные версии обзоров отражены в `data/translation-status.json`; автоматические проверки не заменяют смысловую вычитку. `npm run format:docs` обновляет кликабельное содержание и двуязычную навигацию; `npm run check:docs` проверяет локальные файлы и якоря разделов. `npm run check:translations` сравнивает нумерованные разделы обзоров, число абзацев и идентификаторы/URL источников. Это структурные проверки, а не подтверждение смысловой эквивалентности.

Сервер отдаёт только явно разрешённые публичные файлы, включая английские и русские Markdown-документы из каталога. Исходник сервера и конфигурация не доступны. Контекст сборки должен содержать весь репозиторий: этой версии нужны каталог и обзоры вне `site/`. При развёртывании на Railway измените корень сервиса с `/site` на корень репозитория и используйте `npm start`, только после разрешения на выпуск. Не меняйте существующий деплой ради просмотра этой работы.

## Запросы на исследование

Получатель, утверждённый владельцем: **im@vladimiruzbek.com**, закреплён на сервере. Поля: тема (3–180 символов), вопрос (10–6000), email отправителя, необязательное имя (до 120) и скрытое поле защиты от спама. Запросы отправляются JSON на `POST /api/research-requests`. Имя, email и сообщение передаются через настроенного почтового провайдера владельцу для рассмотрения; отправка не обещает исследования или срока ответа. Не запрашивайте у посетителей чувствительные данные.

Подготовленный адаптер использует [API отправки Resend](https://resend.com/docs/api-reference/emails/send-email). Аккаунт провайдера не создан, расходы не разрешены, домен не настроен, письма не отправлены. Настройте `RESEND_API_KEY`, `MAIL_FROM` (разрешённого проверенного отправителя) и точный `SITE_ORIGIN` (схема и хост, без завершающего слеша) в секретах хостинга. Не помещайте секреты в Git или чат. Переменные должны быть доступны процессу Node; `.env.example` — документация, а не автоматически загружаемая конфигурация.

Без настройки сайт предлагает «Подготовить письмо»: формирует ссылку mailto с введённой темой и вопросом, а посетитель отправляет письмо через свою почтовую программу. В этом режиме POST не выполняется. API продолжает возвращать 503 для прямых запросов без настройки. Ответ 202 в серверном режиме означает принятие сообщения провайдером, а не доказанную доставку в ящик. Ошибки провайдера возвращают 502; неудачные заявки скрыто не сохраняются. Приложение не пишет содержание сообщений и ключи API в журнал. `SITE_ORIGINS` поддерживает список разрешённых источников через запятую для нескольких доменов и имеет приоритет над `SITE_ORIGIN`.

Сервер проверяет поля, принимает JSON с того же источника, ограничивает размер запроса, применяет скрытое поле против ботов и лимит запросов. Лимит в памяти — пять попыток на IP соединения за 15 минут; перезапуск его сбрасывает. За обратным прокси посетители могут разделять лимит; переданным IP-заголовкам намеренно не доверяем. Перед публичным трафиком настройте ограничение на доверенном входном прокси и проверьте его поведение. Несколько экземпляров сервера не разделяют этот счётчик. Одинаковые принятые запросы дедуплицируются в памяти на 15 минут и используют постоянный ключ идемпотентности провайдера. Постоянного ящика заявок и очереди повторных отправок в приложении нет.

## Активация почты и проверка выпуска

- Подтвердить отправителя и аккаунт провайдера с владельцем.
- Проверить доставку в утверждённый ящик и Reply-To одной отдельно разрешённой реальной отправкой.
- Проверить оба языка, мобильный вид, ссылки каталога и документов, ошибки и защиту от спама на целевом хостинге.
- Проверить смысловую эквивалентность английских и русских Markdown-документов.
- Владелец разрешил публикацию 24 октября 2026 года. Каждый проверенный выпуск и его коммит фиксируются отдельно.
